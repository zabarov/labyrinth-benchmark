# Outcome Repair: Implementation and Experimental Findings

## Decision

The bounded local hardening and smoke stage is complete. It is not a stable
release or evidence that weak models reliably solve these tasks through Mirai.
Recorded integration now demonstrates the correction path. Fresh live evidence
still rejects a quality or cost-superiority claim.

## Implemented and Verified

- Runtime result assignments enforce declared state types before mutation.
  A settled effect with an invalid result is not repeated on resume.
- The participant can opt into refinement after native Outcome rejection,
  retaining the original accepted inference and rejected assessment.
- A native read-only accessor reuses existing defect derivation. There is no
  additional runtime, interpreter or authority model in the benchmark.
- Correction uses a bounded child plan, a scoped source patch, full compilation
  and a second Outcome review. Five-call and review budgets are shared at root.
- Replay reconstructs the dependency values used at inference reservation,
  rather than substituting a later resolved parent result.
- Warm candidate reuse still requires source review; cache is not acceptance.

Verification: 430/430 native TaskHost/Cognition/Runtime/Program tests, 43/43 core
benchmark tests, and 2/2 connected reference/source integration tests pass.
The connected tests include successful semantic correction and rejection after
a second failed review. These are recorded fixtures, not model-quality trials.
Failed pre-fix evidence is retained separately.

## Fresh Live Smoke

Fixed `gpt-5.6-luna`, one new synthetic seed, one repeat, length 10,
`system_bundle`. Both participants receive byte-identical text packets; no
ready graph, program, route or oracle is supplied to Mirai. The independent
TypeScript and Python evaluators agree after terminal execution.

| --- | --- | --- | --- |
| Plain | 0/1 | 1 | USD0.00045005 |
| Mirai, scoped repair and Outcome refinement enabled | 0/1 | 3 | USD0.01046130 |

Actual Mirai stages: generation, diagnosis, repair. Generation used invalid
property-access expressions. Diagnosis passed its source-binding checks, but
the proposed repair still failed compilation, result protocol and patch
admission. No Outcome review was reached in this fresh trial. It therefore
does not test live semantic-rejection recovery, despite that feature being
enabled. No success was accepted.

Plain returned an incorrect complete trace: 0/10 correct transitions and value
2 instead of 21. Mirai returned failure. Honest failure is a useful guardrail,
not successful task completion and not proof of better reasoning.

The pair cost USD0.01091135 and introduced no uncertain calls. Across the
campaign, 77 jobs have known estimates of USD5.81601250. Eight historical
unknown calls remain reserved. Including per-call and whole-job uncertainty,
conservative exposure is USD19.71722065, below the owner-approved USD20.
These are journal-based estimates/reserves, not a reconciled provider invoice.

## What This Establishes

The mechanisms for typed execution, bounded correction, non-acceptance of
invalid candidates and historical replay work on the tested fixtures. They
do not supply missing model competence. The successful recorded repair cannot
be substituted for the failed live trial. One seed cannot establish rankings,
statistical significance, weak-model advantage or memory economics.

No additional large or length-1000 campaign is justified by this result.
Further design should reduce the amount of whole-program syntax and integrity
metadata a model must emit, improve defect localization, and validate semantic
admission with independent criteria. Those are follow-up hypotheses, not
automatic permission to change the language or grant execution authority.
